# 独立模拟同行评审

全稿默认 3 份独立报告 + 冻结后综合；片段或用户指定数量按范围调整。目标是检验论证，不预测编辑决定，不假扮真实评审人或编造资历。

1. 明确材料范围、目标期刊/读者与资料缺失。`review-packet` 复制原始稿件、图表、已有来源与共同准则，计算 hash。不得把主代理已发现的问题、倾向性总结或预设结论放进输入包。
2. 预先定义侧重（意义与原创性、方法与统计、解释与外推），每人仍覆盖核心科学有效性。使用宿主独立子代理/进程执行，传相同不可变材料、各自中立任务、公共模板。每个上下文有可追踪 ID。
3. 每个评审只能看到自己的输出位置，不给其它报告、共同问题列表或综合草稿。源包共享只读，输出各自保存；完成后先冻结再比较。
4. 每条问题：稳定 ID、重大/次要、是否阻断中心论点、claim pointer、evidence pointer、实际问题、影响、可检验的解决标准。不能为凑配额制造问题；缺定位标缺失。
5. 按原创性、科学重要性、读者意义、技术可靠性和可读性评价。严重程度来自对结论的影响；Major 不一定 blocking，Minor 不设 blocking。
6. `review-collect` 检查源包未变、报告完整、数量一致和 context ID 不重用。它只能检查声明，独立执行还需宿主日志证明。不能伪造 ID 让检查通过。
7. 冻结后综合共识、分歧、阻断项和修订清单。至少两份独立报告提出同一底层问题才称评审共识；多数票不是科学真伪。共享模型与相同证据源仍可能有相关偏差。
8. 无独立执行工具时交付一份有界评审并明确无法实现互盲，或分次独立调用；不把同上下文三种口吻包装成三名独立审稿。

格式用 assets/templates/reviewer_prompt.md；严谨分析可按需读原 nature-reviewer 的领域检查资料，但其未知路径/工具不能当作已安装依赖。
