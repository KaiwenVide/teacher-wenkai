# 发现、阅读与归档流水线

顺序：研究范围/关键词 → 多源查询和原始日志 → 标识符去重 → 阅读优先级 → 选择原文精读 → 证据表/阅读卡 → 简报 → 归档。

- 每个研究项目独立 init；既有库用 archive 合并并保留快照，不改外部笔记库。关键词变化保留版本。
- `rank` 默认可解释词匹配 70、时效 20、引用量（对数封顶）10；无关键词匹配则 0。最大100。期刊声望/人脉权重0。只是实现一个保守基线，不冒充上游人工六维评分。
- 深度筛选由代理读题名摘要后补方法匹配、实际资源价值、归档价值等带理由的判断。另设证据确定性；高阅读分不代表低偏倚，也不代表适合机制主张。
- 精读前标 full_text/abstract/metadata 可用层级。未读到全文只能写摘要级简报。`digest` 生成元数据骨架，关键结果和评价留待实际阅读，不能用自动填空造结果。
- 归档保存标准元数据、来源、原文/SI、双语笔记、claim links、版本与失败项。已有可用成果保留；重新检索不是重新抹掉人工笔记。
- 每批给查询范围、入库数量、去重、筛选、精读数量、失败和后续动作。失败库可以降级，必须列出实际来源。
- 只有用户请求定时/持续跟踪时才建立宿主自动化；本地脚本不暗设 cron。确认调度工具真实结果，不把一次成功运行当定时任务成功。
- 向邮箱/飞书/Telegram 等发送须有用户明确授权和真实连接；默认交付本地简报，不自动群发。
