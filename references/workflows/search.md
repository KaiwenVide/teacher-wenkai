# 检索与文献管理

按需路由六类任务：多源检索、引文核验、MeSH 策略、本地格式转换、相关论文/标识符管理、引用影响与严格他引。

## 检索

1. 将问题拆成对象/人群、暴露或干预、比较、结果、情境；基础机制问题可用模型—扰动—表型—机制，不强套 PICO。
2. 先用已知种子论文确认词汇，检索 MeSH 的官方术语、同义词和树结构；受控词与题名摘要词并用。保存可复现的 PubMed 查询式，记录字段、布尔括号、截词、日期、人类/动物等限制的理由。不要凭空造 MeSH 词。
3. 为各库分别适配查询语法。同一自然语言字符串不是跨库等价查询。默认生物医学从 PubMed、Europe PMC 起步，Crossref 核 DOI；跨学科增补 OpenAlex/arXiv/S2/CORE。预印本标明未同行评审。
4. `search` 的 limit 是每个数据库上限（1–1000），年份/期刊范围在已取回结果中筛选；它不是穷尽系统检索。系统综述需要扩充分批查询、记录完整分页，并对所有遗漏/访问失败单列说明。
5. `api` 提供 18 个只读 API 的统一 HTTPS/凭据/日志入口。先查该提供商当前官方 API 说明，根据当前官方接口检查路径、返回体、分页和限流，再请求。部分 API 返回 XML，使用 `--raw --out`。返回 200 但有错误体、无全文 body、搜索总量大于取回量都不是成功穷尽。
6. 文献入库保留来源与冲突。精确标识符优先；不同 DOI、arXiv 版本、预印本/正式版不静默混为一篇。同一研究多报告在筛选台账里共享 study_id。
7. 检查 correction/retraction/update，OpenAlex 或 Crossref 的单库标记只是线索；重要引用回到出版方通知。

## 标识符与导出

`lookup` 按 Crossref → DataCite → Handle 回退。`verify` 比较作者、标题、年份、期刊、卷期页/文章号，产生逐字段差异；高风险差异再查出版方和第二独立来源。只查询到了注册元数据时不得声称完成多源互证。

`import-refs` 离线读取 RIS、NBIB、ENW、JSON；BibTeX 用可用的 bibtexparser v1 API。`export` 输出 JSON、CSV、RIS、BibTeX、ENW。RDF 用 `citation` 适配器。保留企业作者、词中重音、作者顺序；显示名不能无依据拆成名和姓。NBIB 原生输出通过 NCBI EFetch，不将 Crossref JSON 伪装成原生 NBIB。

## 引用网络和严格他引

通过 OpenAlex/Semantic Scholar/OpenCitations 获取 references/citations，优先有权限的 WoS/Scopus 作补充并保留各自统计日期。单库计数、数据库总计数和去重取回数分开报告。

默认先报告“无共同作者”，只有用户明确要求严格独立时才在此基础上检查同团队及近期合作。明确合作检查时间窗与已查范围；同机构不是自动同团队，名字相同不是自动同一人。用 ORCID/作者 ID/单位交叉判断。不足标 `unknown_metadata` 或 `probable_external_citation`，不能因查不到关系就确证不存在。

逐篇保存目标 DOI、引用关系来源、共同作者/团队/合作证据、判定、引用段落定位和访问限制。引用语境必须定位原文引用标号；不能从题名猜“正面引用”。院士/Fellow/职位等身份只用当前官方名单核实，不能把引用者地位升级为论文有效性证据。
